
1)   Оба запроса дают одинаковый результат; планы могут отличаться (HashAggregate vs GroupAggregate). ASC подразумевается по умолчанию; регистр влияет на сортировку в зависимости от collation.

2)   SUM(amount) суммирует оба билета, а COUNT(*) посчитает пассажира дважды — нужен COUNT(DISTINCT passenger_id). Для рейсов без билетов нужен LEFT JOIN + COALESCE(SUM(amount),0); INNER JOIN их отбросит.

3)   Город без рейсов должен попасть в результат. NOT IN ломается при NULL в подзапросе (вернёт пусто), NOT EXISTS — безопасен.

4)   Против дублей — DISTINCT или GROUP BY (последний часто эффективнее при агрегатах). Если пассажир есть в boardings, но нет в ticket_flights, всё зависит от того, через какую таблицу идёт JOIN.

5)   DDL возьмёт ACCESS EXCLUSIVE и будет ждать завершения SELECT. В PG 11+ ADD COLUMN ... DEFAULT мгновенен: значение хранится в pg_attribute.attmissingval; смена DEFAULT на true не затронет старые строки. Обычный CREATE INDEX блокирует запись; CONCURRENTLY — нет, но медленнее и рискованнее.

6)   AVG игнорирует NULL, поэтому отменённые рейсы не учитываются. Если aircraft_code NOT NULL — COUNT(aircraft_code) = COUNT(*); иначе первый не считает NULL.
